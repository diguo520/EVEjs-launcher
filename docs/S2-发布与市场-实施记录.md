## 3. 关键设计决策

| # | 决策 | 理由 |
| --- | --- | --- |
| S2-D19 | HTTP 用 **`ureq` 3.4.2 + `native-tls`（schannel）**，不用 `reqwest` / `rustls` | 体积与依赖：`reqwest` 会拖进 tokio + hyper + rustls 整棵树；本机既有 schannel 证书链与系统代理。三件套缺一不可：`TlsProvider::NativeTls`、`RootCerts::PlatformVerifier`（默认 WebPki 会找未启用的内置证书清单）、`win-system-proxy`。**`native-tls-no-default` 不可用**：只编译 `native_tls.rs` 而不开 cargo feature，运行时报 `provider is NativeTls but feature is not enabled` |
| S2-D20 | 进度事件载荷是**数组**：`app.emit("mod:downloadProgress", json!([payload]))` | 与 `channels.rs` 注册的事件形状一致（现役版 `webContents.send(channel, payload)` 也是单值 → 渲染层统一按 `[0]` 取） |
| S2-D21 | `previousHistory()` **复刻为空数组** | 现役版读缓存的**顶层** `mods`，而 `writeCache()` 写的是 `{fetchedAt, index:{mods}}` —— 线上 `history` 恒为 `[]`。分片是 PR 给维护者仓库的共享产物，迁移期不改形状；**正确写法（读 `index.mods`）记入 §4 待办** |
| S2-D22 | `compare_version` 预发布按**纯字符串**比较，非 semver | 与现役版逐字一致（`1.0.0-beta.2` vs `1.0.0-beta.10` 返回 `1`）。属既有行为，照搬并在单测注释里标注 |
| S2-D23 | `read_evejs_version` 三候选 + `??` 语义 | 现役版是 `evejsVersion ?? version`：区分「键不存在」（继续找）与「键存在但非字符串」（也算缺失）；`trim()` 后非空才返回 |

## 4. 与现役版的已知偏差 / 待办

1. **`upload_release_asset` 不需要 node `https` 兜底**：现役版为绕过 Electron `net` 不支持的
   流式上传，另写了一段 `https.request` 分支；`ureq` 能直接 `send(bytes)` 并自动算
   `Content-Length`，故只保留一条路径（更少代码、同样行为）。
2. **`read_repo_file` 的路径编码是手写的 `encode_uri`**：现役版用 `encodeURIComponent`。
   两者对 `!`、`'`、`(`、`)`、`*` 的处理不完全一致；GitHub Contents API 对本仓库的
   文件路径（`mods/`、`*.json`）不受影响，已在单测里锁定 `owner/repo` 形状。
3. **下载进度节流未做**：现役版按时间片节流再发 IPC；本版每 64 KiB 块都回一次回调。
   数据量与现役版同量级，且只在 `marketInstall` / `update:download` 期间发生，暂不优化。
4. **`previous_history` 形状待确认（S2-D21）**：改成读 `index.mods` 才是「正确」语义，
   但会改变提交给维护者仓库的分片内容。**需先与索引仓库维护者确认分片形状**再动，
   当前用单测锁定「恒为空数组」的既有行为。
5. **`ensure_release` / `upload_release_asset` 的同名资产处理**：上传前先删同名资产
   （现役版靠 `?name=` 覆盖失败后重试；本版直接 DELETE + POST，语义相同但更确定）。
