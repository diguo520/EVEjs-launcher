# EvEJS 启动器更新方案

> 状态：建议方案  
> 适用：Electron 启动器，后续源码存放于 Git 仓库  
> 目标：安全、可回滚、可跨平台扩展，并兼容当前 Windows x64 便携版

---

## 1. 结论

推荐采用：

```text
Git 仓库保存源码
GitHub Releases / 自建 Release 服务保存构建产物
启动器启动时读取 update-manifest.json
用户确认后下载新版本
独立 updater 完成热替换
失败自动回滚
```

不要让终端用户通过：

```text
git pull
npm install
npm run build
```

来更新启动器。Git 适合开发和 CI，不适合最终用户更新。

---

## 2. 两类更新对象

### 2.1 启动器自身

包括：

- Electron 主进程
- preload
- renderer HTML/CSS/JS
- bridge
- 内置数据 JSON
- 图标和字体

这部分由本方案负责更新。

### 2.2 EveJS 服务端

包括：

- `server/`
- `config/`
- `externalservices/`
- `_local/gameStore/`
- `Play.bat`

服务端更新不属于启动器自更新范围。启动器只需要检查版本兼容性并提示，不直接覆盖用户配置和存档。

---

## 3. Git 仓库规划

建议将启动器拆成独立仓库，例如：

```text
evejs-launcher/
├── .github/workflows/
├── assets/evejs-launcher/
├── build/
├── docs/
├── scripts/
├── src/
│   ├── main/
│   ├── preload/
│   └── renderer/
├── .gitignore
├── electron-builder.yml
├── package.json
├── package-lock.json
└── tsconfig.json
```

不要提交：

```text
node_modules/
dist/
release/
*.log
launcher-settings.json
临时 updater 下载目录
用户数据库
用户日志
```

大文件如 `manual.html` 再视情况使用 Git LFS。

---

## 4. 版本规则

使用语义化版本：

```text
MAJOR.MINOR.PATCH
```

Git tag：

```text
v1.0.0
v1.1.0
v1.1.1
```

版本来源统一为 `package.json`，禁止多处手写不同版本号。

## 5. Release 产物

每次发布至少生成：

```text
EvEJS-Launcher-1.0.0-x64.exe
EvEJS-Launcher-1.0.0-x64.exe.sha256
update-manifest.json
release-notes.md
```

后续增加：

```text
.exe.sig
sha256 签名文件
```

不要只上传 exe。

## 6. update-manifest.json

```json
{
  "schemaVersion": 1,
  "channel": "stable",
  "version": "1.1.0",
  "minimumVersion": "1.0.0",
  "publishedAt": "2026-09-19T12:00:00Z",
  "releaseNotesUrl": "https://example.com/releases/1.1.0",
  "platforms": {
    "win32-x64": {
      "type": "portable-exe",
      "url": "https://example.com/releases/EvEJS-Launcher-1.1.0-x64.exe",
      "sha256": "....",
      "size": 75534460,
      "signature": "...."
    }
  }
}
```

启动器只执行 manifest 明确允许的更新动作，不执行任意命令。

## 7. 更新通道

支持：

```text
stable
beta
dev
```

配置：

```json
{
  "updateChannel": "stable",
  "autoCheck": true,
  "autoDownload": false,
  "skippedVersion": ""
}
```

规则：

- 稳定用户默认 stable
- beta 用于提前测试
- dev 仅开发者使用
- 默认不自动覆盖
- 允许跳过指定版本
- 不允许未经确认自动降级

---

## 8. 推荐更新流程

1. 启动器延迟 5–10 秒检查更新，避免阻塞启动。
2. 请求 manifest，设置 5–10 秒超时。
3. 比较本地与远端版本。
4. 有更新则提示用户。
5. 用户确认后下载到临时目录。
6. 下载为 `.part` 文件。
7. 校验 SHA256、大小和签名。
8. 校验失败删除文件，保留旧版本。
9. 启动独立 updater。
10. updater 等待当前进程退出并替换 exe。
11. 新版本启动成功后删除备份。
12. 失败则恢复旧版本。

---

## 9. 独立 updater

便携 exe 正在运行时不能覆盖自身，必须使用独立 updater。

```text
当前启动器
  ↓
updater.exe --pid <PID> --new <新exe> --target <当前exe>
  ↓
等待当前进程退出
  ↓
旧 exe 重命名为 .backup
  ↓
复制新 exe 到目标位置
  ↓
启动新 exe --updated
  ↓
成功则删除备份；失败则恢复备份
```

推荐用独立 Go 小程序实现。

不建议长期使用 PowerShell/BAT 作为 updater。

## 10. Electron 接入

新增：

```text
src/main/updater.ts
src/preload/update.ts
src/renderer/updater-ui.js
```

IPC：

```text
update:check
update:download
update:apply
update:state
update:cancel
```

状态：

```ts
type UpdateState =
  | "idle"
  | "checking"
  | "available"
  | "downloading"
  | "ready"
  | "applying"
  | "error";
```

UI 显示当前版本、最新版本、通道、更新日志、下载进度、跳过版本和“重启并更新”。

更新前如果 owned 服务正在运行，必须提示先停止。

## 11. 安全要求

- 只使用 HTTPS
- 校验 SHA256
- 推荐 Windows 代码签名
- 禁止执行 manifest 中的任意命令
- 禁止降级到低于 minimumVersion
- 更新失败必须保留旧版本
- updater 日志不得记录密码或令牌
- 不更新用户数据库、服务端配置和存档

---

## 12. 服务端兼容性

manifest 增加：

```json
{
  "serverCompatibility": {
    "minimum": "0.12.8",
    "maximum": "0.13.x"
  }
}
```

更新前检查当前服务端、客户端、配置 schema 和数据库 schema。

## 13. Git/CI 发布

推荐 GitHub Actions：

```yaml
name: Release Launcher
on:
  push:
    tags:
      - "v*"
jobs:
  build:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm run build
      - run: npx electron-builder --win portable --x64
      - run: sha256sum release/EvEJS-*.exe > release/SHA256SUMS
      - uses: softprops/action-gh-release@v2
        with:
          files: release/*
```

发布顺序：

1. 更新 package version 和 CHANGELOG
2. 创建 tag
3. CI 构建和测试
4. 上传 exe、checksum、manifest
5. 先发 beta
6. 验证更新、回滚和服务控制
7. 再发 stable

## 14. 回滚

新版本启动后写入：

```text
%LOCALAPPDATA%/EvEJS Launcher/update-health.json
```

如果新版本连续启动失败，updater 自动恢复 `.backup`。

回滚触发条件：

- 新版本无法启动
- preload 加载失败
- renderer 连续崩溃
- 更新校验失败
- 用户手动回滚

## 15. 分阶段实施

### 阶段 1：Git + 手动更新
- 源码进入 Git
- CI 构建 Release
- 提供 exe、SHA256、manifest
- 启动器检查并提示更新

### 阶段 2：自动下载
- 下载到临时目录
- 校验 SHA256
- 提示重启更新

### 阶段 3：自动替换
- 独立 updater
- 备份、替换、回滚
- `--updated` 清理旧版本

### 阶段 4：多平台多通道
- Windows x64
- stable/beta/dev
- Linux AppImage/deb
- macOS zip/dmg
- 服务端兼容矩阵

## 16. 验收标准

- [ ] Git 不包含 node_modules/dist/release
- [ ] tag 自动生成 Release
- [ ] Release 包含 exe、SHA256、manifest、说明
- [ ] 启动器可检查更新
- [ ] 下载可重试
- [ ] 校验失败不会覆盖旧版本
- [ ] 更新前提示停止服务
- [ ] 更新后账号、配置、日志和数据库不受影响

- [ ] 更新不依赖 npm、Node、Git
- [ ] 支持 stable/beta
- [ ] 支持跳过版本

## 17. 最终建议

当前最合适方案：

```text
Git 保存源码
GitHub Release 保存构建产物
update-manifest.json 描述版本
独立 Go updater 完成替换和回滚
stable/beta 双通道
```

不要用 git pull 给最终用户更新，不要把 exe 和 node_modules 提交到 Git，也不要让运行中的 Electron exe 覆盖自身。

## 18. 单文件便携 exe 自动更新方案

用户只运行一个便携 exe，也不要求维护额外缓存目录时，仍然可以自动更新。Windows 不允许覆盖正在运行的 exe，因此必须临时启动一个 updater 完成替换。

### 18.1 运行时真实路径

electron-builder 便携版会设置：

```text
PORTABLE_EXECUTABLE_FILE
PORTABLE_EXECUTABLE_DIR
```

含义：

- `PORTABLE_EXECUTABLE_FILE`：用户双击并看到的原始便携 exe 完整路径
- `PORTABLE_EXECUTABLE_DIR`：原始 exe 所在目录

不能使用 `app.getPath("exe")` 作为更新目标，因为它指向 Electron 解压后的临时 exe，不是用户原来的便携 exe。

### 18.2 临时文件位置

不需要创建长期缓存目录，只需要系统临时目录：

```text
%TEMP%\EveJS-Launcher-Updater\
```

更新结束后删除。

新版本 exe 可以使用同目录临时文件：

```text
<原exe目录>\EvEJS-Launcher.exe.new
```

同目录重命名更可靠，也能尽量避免跨磁盘复制问题。

### 18.3 更新流程

```text
启动器读取 update-manifest.json
  ↓
下载新 exe 到 %TEMP% 或同目录 .new
  ↓
校验 SHA256 / 代码签名
  ↓
从 resources 提取 evejs-updater.exe 到 %TEMP%
  ↓
启动 updater：
  evejs-updater.exe
    --target "<PORTABLE_EXECUTABLE_FILE>"
    --source "<新exe路径>"
    --pid <Electron PID>
    --parent-pid <便携版包装器 PID>
  ↓
当前启动器退出
  ↓
updater 等待两个 PID 退出
  ↓
原 exe 重命名为 .backup
  ↓
.new 或下载文件重命名为原 exe
  ↓
启动新 exe --updated
  ↓
新版本成功启动后删除 .backup 和 %TEMP%
  ↓
失败则恢复 .backup
```

### 18.4 updater 打包方式

建议新增独立小程序：

```text
evejs-updater.exe
```

通过 `electron-builder.yml` 打入资源：

```yaml
extraResources:
  - from: updater/evejs-updater.exe
    to: evejs-updater.exe
```

启动器运行时把它复制到：

```text
%TEMP%\EveJS-Launcher-Updater\evejs-updater.exe
```

然后启动它。当前启动器退出后，updater 完成替换。

### 18.5 无缓存目录原则

- 不创建用户需要管理的 `updates/` 文件夹
- 不在 exe 旁边保留版本目录
- 下载完成后只保留临时 `.new` 文件
- 替换成功后删除 `.backup` 和临时目录
- 失败时保留 `.backup`，恢复旧版本

### 18.6 权限问题

如果 exe 放在：

- U 盘
- `E:\Games\...`
- 用户可写目录

通常可以直接更新。

如果放在：

- `C:\Program Files`
- 其他需要管理员权限的目录

更新器无法写入时，应提示用户：

```text
当前目录不可写，请将启动器移动到用户可写目录，或使用安装版启动器。
```

建议不要静默请求管理员权限，除非产品明确要求 UAC 流程。

### 18.7 推荐结论

保留当前单文件便携 exe 形态时，采用：

```text
系统临时目录 updater
+ 原始便携 exe 路径定位
+ 同目录 .new 替换
+ .backup 回滚
```

这样用户：

- 不需要手动下载
- 不需要维护缓存文件夹
- 不需要 Node、npm、Git
- 仍然可以获得自动更新

核心限制只有一个：更新期间必须短暂写入 `%TEMP%`，这是 Windows 运行便携 Electron 本身就已经依赖的系统临时目录。

## 19. 运行中更新、自动重启和任意路径

### 19.1 启动器正在运行时能否更新

可以更新，但不能原地覆盖正在运行的 exe。

正确流程：

```text
用户点击“重启并更新”
  ↓
启动器下载新版本并校验
  ↓
启动临时 updater
  ↓
当前启动器退出
  ↓
updater 等待旧进程完全退出
  ↓
替换 exe
  ↓
updater 启动新版本
```

用户看到的效果是：

```text
启动器关闭一次
→ 更新
→ 自动重新打开新版本
```

如果当前有 owned 服务正在运行，推荐先询问或自动停止服务，再执行更新。否则旧启动器退出时可能清理服务进程。

### 19.2 更新后自动启动

updater 完成替换后必须自动启动目标 exe：

```text
evejs-updater.exe \
  --target "<原启动器路径>" \
  --source "<新版本路径>" \
  --pid <旧ElectronPID> \
  --parent-pid <旧便携包装器PID> \
  --restart
```

`--restart` 表示替换成功后自动启动新版本。

新版本可以接收：

```text
--updated --from 1.0.0
```

用于：

- 显示“已更新到 1.1.0”
- 清理 `.backup`
- 清理临时 updater 目录
- 根据更新前状态恢复主服务器和市场服务

服务恢复建议：

- 更新前记录是否运行过 `mainServer`、`marketServer`
- 默认不自动启动客户端
- 用户可设置“更新后恢复服务”

### 19.3 任意存放路径

不能写死：

```text
E:\Games\EveJS-v0.12.8\launcher\launcher\release\EvEJSLauncher.exe
```

也不能假设 exe 名称、盘符或目录深度。

便携版运行时使用：

```text
process.env.PORTABLE_EXECUTABLE_FILE
process.env.PORTABLE_EXECUTABLE_DIR
```

安装版运行时使用：

```text
process.execPath
app.getPath("exe")
```

优先级：

```text
PORTABLE_EXECUTABLE_FILE
→ process.execPath
→ app.getPath("exe")
```

updater 必须接收绝对 `--target` 路径，不自行拼接固定路径。

### 19.4 需要支持的路径情况

- 空格路径：`E:\My Games\EveJS Launcher.exe`
- 中文路径：`D:\游戏\EveJS 启动器.exe`
- 括号路径：`C:\Tools (x64)\Launcher.exe`
- 大小写不同：`E:\...` / `e:\...`
- U 盘和移动硬盘
- 多份便携版并存
- 用户更新前移动了 exe

Windows 下启动 updater 必须使用参数数组，不要拼 `cmd` 字符串：

```ts
spawn(updaterPath, [
  "--target", targetPath,
  "--source", sourcePath,
  "--pid", String(process.pid),
  "--parent-pid", String(process.ppid),
  "--restart"
]);
```

不要使用：

```text
cmd.exe /c "... " + 用户路径
```

否则空格、中文和特殊字符容易出错。

### 19.5 用户移动了启动器怎么办

更新开始前记录：

```json
{
  "target": "<PORTABLE_EXECUTABLE_FILE>",
  "hash": "<当前exe SHA256>",
  "startedAt": "..."
}
```

应用更新前再次检查：

- 目标文件仍存在
- 目标文件 SHA256 没有变化
- 目标路径仍是当前运行实例

如果不一致：

```text
中止更新
删除临时新文件
提示用户重新启动启动器后重试
```

不能把新版本强行写到旧路径。

### 19.6 不可写路径

以下路径可能无法自动替换：

- `C:\Program Files`
- Program Files (x86)
- 系统目录
- 只读介质
- 网络共享
- 被 OneDrive 锁定的目录
- 被其他进程占用的便携 exe

处理：

1. 便携版：提示移动到用户可写目录
2. 安装版：使用 UAC 更新
3. 网络共享：建议复制到本地目录运行
4. 多份副本：只更新当前运行的那份

不建议在便携版中静默请求管理员权限。

### 19.7 多份便携版并存

用户可能有：

```text
D:\Games\EveJS\Launcher.exe
E:\Tools\Launcher.exe
U:\EveJS\Launcher.exe
```

规则：

- 每次只更新当前运行的 exe
- 其他副本下次启动时自行检查更新
- manifest 是共享的，但目标路径必须来自当前进程
- 不扫描其他目录，不自动更新其他副本

### 19.8 更新后的状态恢复

更新前记录：

```text
主服务器是否运行
市场服务是否运行
更新通道
更新前版本
```

默认行为：

- 启动器自动重新打开
- 主服务器和市场服务按用户设置恢复
- 客户端不自动恢复
- 账号、配置、日志、数据库不迁移、不覆盖

### 19.9 推荐结论

支持：

- 启动器运行时更新
- 更新后自动重新启动
- 任意盘符、目录、中文和空格路径
- 无用户缓存文件夹
- 临时使用 `%TEMP%`
- 失败自动回滚

不允许：

- 覆盖正在运行的 exe
- 固定写死启动器路径
- 在不可写目录静默失败
- 通过 `git pull` 更新最终用户

## 20. 当前 Electron 启动器实现映射

本节记录已经落地到代码中的实现，不再只是建议项。

| 方案能力 | 当前实现位置 |
| --- | --- |
| 更新弹窗与进度交互 | `src/renderer/public/eve-launcher.html` |
| 原型 DOM → 真实 IPC 桥接 | `src/renderer/public/launcher-bridge.js` |
| 清单读取、版本比较、下载、SHA256 | `src/main/updater.ts` |
| 更新 IPC 白名单 | `src/main/ipc.ts`、`src/preload/index.ts` |
| 独立替换器 | `updater/main.go` |
| 替换器打包 | `electron-builder.yml` 的 `extraResources` |

当前清单地址优先级：

```text
EVEJS_UPDATE_MANIFEST_URL
→ userData/launcher-settings.json 的 updateManifestUrl
→ 便携版 exe 同目录 launcher.config.json 的 updateManifestUrl
→ https://github.com/diguo520/EVEjs-launcher/releases/latest/download/update-manifest.json
```

默认使用 GitHub Latest Release，因此便携版无需额外携带 `launcher.config.json` 也能检查更新。配置文件支持 UTF-8 BOM，不会因为 Windows 编辑器写入 BOM 而失效。

启动器运行期间不会要求用户关闭后再检查：启动约 5 秒后检查一次，之后每 30 分钟检查一次；窗口重新获得焦点时，如果距离上次检查超过 5 分钟，也会再次检查。发现新版本时显示顶部红点并提示用户。

更新弹窗中的版本日志来自当前 Release 的 `update-manifest.json`。CI 生成清单时优先读取：

```text
release-notes/vX.Y.Z.json
```

如果该文件不存在，则回退读取上一个 Git 标签到当前标签之间的提交标题，并按 `feat / fix / 其他` 转换为 `new / fix / opt`。正式发布建议始终提供专用版本说明，避免把内部提交信息直接展示给最终用户。

多语言版本说明使用以下结构：

```json
{
  "version": "0.1.10",
  "changelog": {
    "zh": [
      { "type": "new", "text": "中文更新说明" }
    ],
    "en": [
      { "type": "new", "text": "English release note" }
    ]
  }
}
```

启动器根据当前 `curLang` 选择日志：`zh` 使用中文，其他语言使用英文。旧格式的单数组 `changelog` 仍然兼容；Git 提交日志回退模式无法自动翻译，只应作为没有正式版本说明时的兜底。

当前下载目录：

```text
%TEMP%\EveJS-Launcher-Updater\<version>\
```

当前目标路径：

```text
PORTABLE_EXECUTABLE_FILE
→ process.execPath
```

安装前会检查主服务器和市场服务是否仍在运行；只要有活动服务就阻止替换。替换成功后 updater 使用原目标路径重新启动，因此用户把便携版放在任意盘符、中文目录或空格目录都可以继续更新。
