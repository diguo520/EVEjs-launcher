## 3. 关键设计决策

| # | 决策 | 理由 |
| --- | --- | --- |
| S2-D24 | 替换 exe 的活**继续交给现役版的 Go 更新器**，Go 侧一行不改 | 它本来就与外壳框架无关（`--target/--source/--pid/--from/--to/--restart`），重写成 Rust 只会多一份要维护的「杀自己再替换自己」逻辑；唯一的适配是 `--parent-pid 0`（Tauri 便携版没有 Electron 的 portable 包装进程，Go 侧 `<=0` 即跳过等待） |
| S2-D25 | 拉起更新器用 `DETACHED_PROCESS \| CREATE_NEW_PROCESS_GROUP` | 与 `process.rs` 直连客户端的口径一致；`windowsHide` 对应的 `CREATE_NO_WINDOW` 与 `DETACHED_PROCESS` 语义互斥（后者本来就不分配控制台），两个一起给只会互相抵消 |
| S2-D26 | 取消下载用 `net::download_cancellable` 的**块间轮询**，取消后最终状态是 `idle` | `ureq` 没有「中断正在等的 socket」的口子，只能每 64 KiB 问一次取消标志；现役版 abort 后会被 catch 覆盖成 `error`（用户主动取消却报错），本次修正为保持 `idle` |
| S2-D27 | `update:changed` 载荷是**数组**：`app.emit("update:changed", json!([state]))` | 延续 S2-D20；渲染层 shim 的 `on()` 按位置展开成回调参数，两种形状都能用，统一成数组少一条特例 |
| S2-D28 | 打包态判定用 `!cfg!(debug_assertions)` 近似 `app.isPackaged` | Tauri 侧没有等价的运行时标志；release 构建即「已打包」，dev（`cargo run`）走 `cwd`，与 Electron 行为一致 |
| S2-D29 | 更新器查找顺序：`EVEJS_UPDATER_DIR` → `<exeDir>/evejs-updater.exe` → `<exeDir>/_launcher/updater/` → `<exeDir>/resources/` → `../vendor/updater/bin/` | 前四级覆盖「覆盖安装 / Electron 便携版布局 / 新便携版布局 / extraResources 布局」，最后一级让 `cargo run` 无需先拷贝（对齐 `sidecar::script_path` 的思路）；新便携版布局与 `_launcher/cli/` 对称 |
| S2-D30 | 清单与更新包的下载超时分别设 30s / 600s | 现役版 `net.fetch` 没有显式超时（下载只能手动取消），客户端一旦遇上黑洞地址会永远转圈；给宽松上限只为兜底，正常路径不受影响 |

## 4. 与现役版的已知偏差

1. **取消下载后停在 `idle`**：见 S2-D26。现役版会先广播 `idle`、再被 `downloadUpdate` 的 catch 覆盖成
   `error`（文案是 AbortError 的英文原文）；本次改成「取消就是取消」，回包 `{ok:false, reason:"已取消下载"}`。
2. **UA 统一成 `EveJS-Launcher`**：现役版更新链路用 `EvEJS-Launcher/{version}`（带版本号）。
   本版所有出网请求都走 `net.rs` 的单一 UA（见 S2-D19），不为更新器在出网层再开口子；
   GitHub Release / Pages 不按 UA 分流，功能无影响。
3. **下载有超时**：见 S2-D30。
4. **`file://` 清单只解 `%20`，且 S3 起默认禁用**：现役版用 `new URL()` 做完整百分号解码。
   这个分支只服务「开发期指一个本地清单」，路径里有 `%`、`#`、`?` 的极端情况不再支持。
   **A1 落地后打包版一律只认 https**（`file://`/本地路径不再自动生效），
   需要本地升级演练时显式设置 `EVEJS_UPDATE_ALLOW_LOCAL=1`（见 `docs/S3-查重与审核-实施记录.md`）。
5. **`update:apply` 的「已打包」判定**：见 S2-D28；现役版还能靠 `app.isPackaged` 区分
   「打包但非便携」的情况，本版把 `PORTABLE_EXECUTABLE_DIR` 的缺失也当成 dev。
6. **更新器查找顺序多了两级**：见 S2-D29（`EVEJS_UPDATER_DIR` 与 `_launcher/updater/`）；
   现役版只有 `resourcesPath` 与「源码相对路径」两条。
