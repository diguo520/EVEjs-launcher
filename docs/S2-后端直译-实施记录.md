## 3. 关键设计决策

| # | 决策 | 理由 |
| --- | --- | --- |
| S2-D1 | 账号 / 数据库**继续用仓库自带的 Node CLI**，不重写进 Rust | 与服务端共用同一套密码哈希（`SHA1(pw_utf16le ‖ user_lower_utf16le)×1000`）与库表结构，重写等于制造第二套真相；低频操作，冷启动开销可接受 |
| S2-D2 | DPAPI 只 `#[link]` 3 个符号（`CryptProtectData`/`CryptUnprotectData`/`LocalFree`） | 引 `windows` crate 会拖慢编译、增大体积，与极小体积目标相悖；解密失败一律退化为「没存过密码」，绝不阻塞启动 |
| S2-D3 | 客户端**绝不传 `windowsHide`**，用 `DETACHED_PROCESS(0x8)｜CREATE_NEW_PROCESS_GROUP(0x200)` + stdio ignore | 计划 B8：`SW_HIDE` 会被应用到 GUI 子系统的 `exefile.exe` 首次显示，导致「进程在跑、有声音、看不到窗口」。已在代码里留了防回归注释 |
| S2-D4 | 客户端 PID 记进 `ServiceTable`，`stop_tree` 同时看 PTY 与它 | 客户端是 DETACHED 直连、没有 PTY 会话，否则 `service:stop` 会把自启客户端误判成「外部进程，不接管」 |
| S2-D5 | 启动后 6 s 观察窗 + 350 ms 日志尾随（按整行推送，单块上限 64 KB） | 早期崩溃（证书 / 资源 / 配置错）立刻反馈 UI；尾随产出直接喂 `terminal:data` 的 `client` 页签 |
| S2-D6 | 初始化**单任务串行**，临时 bat 用 `cmd.exe /d /c call <bat>` | 现役版语义；`/s` + 手写引号会把带引号整串当命令名（含空格路径必炸） |
| S2-D7 | 生成的 db bat 不含中文注释（说明移到 Rust 注释） | bat 保持纯 ASCII，避免 chcp 生效前后 cmd 用不同代码页解析出乱码行；已有单测 `bat_tasks_are_ascii_with_cp65001` 守住 |
| S2-D8 | `init:changed` 的进度只在「同一任务 key」时更新 | 防止旧任务的迟到输出把新任务的进度条打回去 |
| S2-D9 | 客户端日志文件名自带时间戳用自研 `civil_from_days` 换算 | 对齐现役版 `new Date().toISOString().replace(/[:.]/g,"-")`，但不必为此引入 `chrono`/`time` |

## 4. 顺带修掉的 S1 门禁缺陷

| # | 现象 | 修法 |
| --- | --- | --- |
| F1 | 生成产物 `channels.rs` 的条目超过 rustfmt `max_width`，一旦执行 `cargo fmt` 就被拆成多行，`verify-contract.mjs` 的单行正则随即解析出 0 条；文件末尾的生成型单测同理（`cargo fmt --check` 在「重新生成」后会再次失败） | 生成器改为输出 **rustfmt 恒等形式**：`CHANNELS` 加 `#[rustfmt::skip]`，单测里的链式调用与 `assert!` 按展开写法逐行输出；校验正则同时改成容忍空白（双保险）。现在「生成 → `cargo fmt --check`」恒等 |
| F2 | `smoke.rs` 硬编码「14 个只读 + 56 个待实现 = 70」 | 改为 `20 + registry::PLANNED.len()`，并把 6 个**只读**新通道（`accounts:list/checkRunning/verify`、`database:overview/table/backups`）纳入自检，让新代码进入真实 WebView 覆盖 |

### 5.1 真机验证（直接跑仓库自带 CLI，参数与 Rust 侧完全一致）

对着现役安装 `E:\Games\EveJS-v0.12.8` 只读执行：

```text
node vendor/cli/account-cli.js check-running E:\Games\EveJS-v0.12.8
  → {"running":false,"ports":[30000,11,2,127,26000,26002,26400],"listening":[]}

node vendor/cli/database-cli.js overview E:\Games\EveJS-v0.12.8
  → {"ok":true,"path":"...\\_local\\gameStore\\gamestore.sqlite","sizeBytes":22065152,
     "tableCount":116,"totalRows":6961,"journalMode":"wal"}

node vendor/cli/account-cli.js list E:\Games\EveJS-v0.12.8
  → 3 个账号；accountKey="test" / isGM=true / roles[0].characterId="140000001"（字符串）
```

几点结论：

1. 参数顺序（`<cmd> <root> [args]`）与 `db.rs` / `accounts.rs` 的拼参完全对得上；
2. `roles[].characterId` 是**字符串**，`accounts.rs` 的取值逻辑同时兼容字符串与数字；
3. 这份真实输出已固化成单测夹具 `list_postprocess_matches_electron_on_real_cli_payload`，
   断言 `hasStoredCredential` / `avatar=null` 注入正确、原字段（含嵌套 `location`、数值型 `isk`/`skillPoints`）一个不丢。

> 未做「Rust → 真仓库」全链路 e2e 的原因：现役安装的仓库布局（`server/index.js`）与新启动器的
> `isRepoRoot`（要求 `server/autostart.js`）不一致，而临时 shim 仓库无法复用 `better-sqlite3`
> 的原生 `bindings` 依赖。因此改为「CLI 用真数据验参数与形状 + Rust 侧用夹具验变换」两段拼合，
> 与 S1 的 `smoke-ipc.ps1` 一起覆盖。
