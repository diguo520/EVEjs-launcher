## 2. 关键决策

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| **S4-D01** | **UI 资产内嵌 exe，Node 侧车与自更新器外置 `_launcher/`** | 10.97 MB 的 `ui/dist` 走 `frontendDist` 内嵌（≤20 MB 阈值内，双击即用）；而 `account-cli.js` / `database-cli.js` / `evejs-updater.exe` 必须是**磁盘上真实存在的文件**（服务端 Node 直接执行、更新器要能被替换），塞进 exe 就得每次启动解压到临时目录，反而更慢更脏。代价：分发物是「目录 + zip」而不是单 exe |
| **S4-D02** | **NSIS 安装包也做**（不只便携版） | 便携版没有安装器，用户机器缺 WebView2 时只能靠我们的中文引导手动装；NSIS 那条路 `webviewInstallMode: downloadBootstrapper` 能自动补齐运行时。两条轨道各有场景，成本只有脚本里一个 `-Nsis` 开关 |
| **S4-D03** | **exe 内部名保持不变**（`EvEJSLauncher.exe`），只让 zip / setup **文件名**带 `-Tauri-<version>` | 自更新器按进程名替换自身、用户也可能建了快捷方式；靠「包名区分双轨」而不是「改 exe 名」，把 A5 双轨的风险降到最低 |
| **S4-D04** | 版本**唯一真源 = `package.json`**，`tauri.conf.json` 与 `Cargo.toml [package]` 由脚本回写 | 三处手改必然漂移；`--check` 进 `build.ps1` 与 `npm run check`，漂移直接 fail（cargo 侧只改 `[package]` 段，不碰依赖表） |
| **S4-D05** | manifest 字段**以 Rust 读取口径为准**：`platforms["win32-x64"].{url,sha256,size}` | JS 生成、Rust 验签读取，字段名最容易各写一套（曾差点写成 `sizeBytes`）。用 `tests/parity/fixtures/manifest` 的 3 条固定向量把两侧钉死 |
| **S4-D06** | WebView2 预检**放在创建窗口之前**，且探测顺序按「WOW6432Node → 64 位 → WOW6432 位标志 → HKCU」 | 本机实测 `pv` 只写在 `HKLM\SOFTWARE\WOW6432Node\...` 下；且 `KEY_WOW64_32KEY(0x200)` 对 `RegOpenKeyEx` 有效、传给 `RegGetValueW` 会直接 `ERROR_INVALID_PARAMETER` —— 必须用 `RRF_SUBKEY_WOW6432KEY(0x0001_0000)` |
| **S4-D07** | 把「未装 WebView2」做成**可自动化的诊断开关**（`EVEJS_SIMULATE_NO_WEBVIEW2=1`）+ 标题断言脚本 | 否则这条验收只能靠「手动卸载 WebView2」或「找一台干净机器」，永远无法进 CI。开关只影响本条预检，不改任何权限或数据路径；断言方式：进程必须**存活**（在等用户选）且顶层窗口标题 == 中文指引 |
| **S4-D08** | 体积门禁**同时卡 exe 与 zip**；zip 断言默认「存在即卡」，`--require-zip` 才把「缺失」也算失败 | `size-gate.mjs` 是 `build.ps1` 的第 9 步（此时还没打包），若默认要求 zip 存在，干净构建必然误报；打包后由 `package.ps1` 调 `--require-zip` 复检，两处都不放松 |
| **S4-D09** | NSIS 打包完**用暂存副本还原 `target/release` 的 exe** | Tauri CLI 会**就地**给 exe 打上 `bundle type information: nsis`（实测 6,474,240 → 6,504,960 字节，哈希也变），被打过标记的 exe 不再等同于便携版；不还原的话 size-gate 度量的和用户拿到的就不是同一个东西 |
| **S4-D10** | 便携版 README 写清「不要只拷 exe，`_launcher` 必须一起拷」 | 这是外置策略（S4-D01）唯一的坑，必须在用户看得见的地方说一次 |
| **S4-D11** | 首启闪屏用 `background_color` **在 Rust 侧**设置，而不是写进 `tauri.conf.json` 的 `app.windows` | 窗口是 Rust 侧 `WebviewWindowBuilder` 建的，配置文件里的窗口设置不生效；颜色取 UI 的 `--bg-void` (#05080d) 而不是计划草案里的 #0b0e14，避免"先黑后亮" |

### 5.1 收口时抓到的**打包缺陷**：便携 zip 里混进了运行态（含私钥）—— 已修

S6 收口重打时逐条核对 zip 内容才暴露：`package.ps1` 原来是把 `target/release/_launcher`
**整目录**拷进暂存目录的，而那个目录在跑过自检 / parity / e2e / 更新演练之后会多出：

| 混进包里的东西 | 内容 | 后果 |
| --- | --- | --- |
| `_launcher/data/mod-keys/*.key` + `data/author.json` | 本机模组作者私钥（DPAPI 密文）与作者身份（`{"id":"au-…","name":"指挥官",…}`） | **直接违反 `author.rs:5` 写下的不变量**：「只落在 `_launcher/data/mod-keys/`，永不上传、永不打包」 |
| `_launcher/data/launcher-settings.json` | 测试运行的窗口位置（如 `x:768,y:255,1693x905`），还可能含账号凭据密文 | 用户首次启动就继承一个奇怪的窗口位置 |
| `_launcher/cache/mod-index.json` | 市场索引 TTL 缓存 | 用户首启读的是过期索引，而不是自己拉一次 |
| `_launcher/{crash,logs,temp}` | 运行目录 | 无意义噪声 |

这些都是**每台机器首次运行时由应用自己创建**的，所以改成白名单：只搬 `cli` / `updater`（构建产物），
并在暂存后断言 `data`/`cache`/`crash`/`logs`/`temp`/`mods` 一个都不许出现（防回归）。
顺带把这条写进发布检查单（`docs/S7-发布与回滚-实施记录.md` §5.1）。

> 为什么之前没被发现：S4 那次打包后没有逐条核对 zip 内容，而 `size-gate` 只看体积、`npm run check` 只看源码。
> 教训与 L8 那条一样 —— **产物的「内容」也要有断言**，不能只看它的大小。

## 6. G4 实机清单（人工，一次 30 分钟）

1. **干净 Win10 21H2**（或 1809）与 **Win11 各一台**：解压便携版 zip → 双击 `EvEJSLauncher.exe` → 出现主窗口（不是白屏）；
2. 同机**故意卸载 WebView2**（或全新装且未预置的 Win10 1809）：双击应弹中文指引；点「是」应打开浏览器下载页；装完再双击能正常启动；
3. NSIS 安装包在**缺 WebView2** 的机器上应自动补齐运行时（`downloadBootstrapper`）；
4. 记录：冷启动耗时、主窗口出现时间、任务管理器内存（与 `docs/baseline.md` 同口径）。

> 本机可自动化的部分（1 之外的全部逻辑）已由 `smoke-ipc.ps1` 与 `smoke-webview2-missing.ps1` 覆盖。

## 7. 启动耗时口径修正（重要）

`docs/baseline.md` 里的启动耗时是用 `Process.MainWindowHandle` 判定的，而
`tauri-plugin-single-instance` 会在主窗口之前创建自己的顶层窗口（标题 `com.evejs.launcher-siw`），
所以那个口径实际测的是**单实例插件建窗口**的时间，而不是「用户看见启动器」的时间：

| 口径 | 判定依据 | 本次实测 |
| --- | --- | --- |
| 旧（`baseline.md`，偏乐观） | `Process.MainWindowHandle != 0` | **约 555 ms**（抓到的是 `com.evejs.launcher-siw`） |
| 新（本 S4 修正） | EnumWindows 精确匹配「可见 + 标题 == `EvEJS 启动器`」 | **平均 1130 ms**（1091 / 1091 / 1207） |

- 修正方式：`scripts/measure-startup.ps1` 改为按标题定位主窗口；旧的 `-Exe` / `-Iterations` /
  `-SampleSeconds` / `-OutFile` 用法保持不变，新增 `-WindowTitle`。
- **对比结论不变**：Electron 的 10.8 s（冷启）同样是「到窗口出现」，量级差 10 倍以上依旧成立；
  但绝对数字要用新的 1.13 s，`baseline.md` 的 0.64 s 也应按新口径重测（已在该文档加注）。
- 内存结论不变：425 MB（Tauri）vs 398 MB（Electron 现役）——**换外壳不省内存**，S6 页面瘦身才是解药。
