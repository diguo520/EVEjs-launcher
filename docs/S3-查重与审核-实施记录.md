## 2. 关键决策

| # | 决策 | 理由 |
| --- | --- | --- |
| **S3-D01** | A1 采取 **fail closed**：`UPDATE_PUBKEY` 为空串时 `verify_update_manifest` 直接拒绝一切更新，而不是「跳过验签」 | 「忘配公钥」是最可能发生的运维失误，降级成「不验签」等于把 A1 的修复原地推翻；空公钥拒绝可以立刻暴露问题（`audit-security.mjs` 会把它列成债务而不是静默通过） |
| **S3-D02** | 签名负载 = `canonical_manifest_json`（递归 key 升序、去顶层 `signature`、`JSON.stringify`），JS 侧 `gen-update-key.mjs` 逐字节复刻 | 验签跨语言，规范化差一个空格就永久验不过；用固定向量（种子私钥 = `sha256("evejs-s3-parity-fixture")`）做 **JS 签 → Rust 验** 的交叉验证，`updater.rs::js_signed_manifest_verifies_in_rust` 把这个向量钉死 |
| **S3-D03** | A2 的 `trusted` 只认 **索引背书**（`endorsement_from_index`），包内自带的签名/自称一律降级为「未签名」 | 「包自己说自己是官方的」没有任何信任价值；唯一可信来源是仓库索引里的 sha256 |
| **S3-D04** | A3 在**解压前**逐条检查 entry 名（归一化后必须在 tempRoot 内、拒绝对路径、拒绝符号链接），而不是解压后再清理 | 先落地再检查等于已经写完盘；符号链接必须在 `cpSync` 之前拦住 |
| **S3-D05** | A4 把集成测试用的 `self_test_report` 挪进 `--self-test` 分支注册，生产构建只暴露 `launcher_invoke` 一个命令 | 「只注册白名单 command」不是口号：命令数量本身就缩减到 1（`audit-security.mjs` 会比对 `#[tauri::command]` 声明、注册点与白名单三者） |
| **S3-D06** | shim 的传输层改用 `window.__TAURI_INTERNALS__`（与官方 `@tauri-apps/api` 同款），事件订阅直接走 `plugin:event\|listen\|unlisten` | `withGlobalTauri:false` 后 `window.__TAURI__` 不存在；用官方内部协议而不是自造 `postMessage` 桥，`verify-contract.mjs` 会拒绝 `.ipc`/`.postMessage`/`.runCallback` 等旧写法 |
| **S3-D07** | A4 真机断言**不能**用 `eval` 当 CSP 探针（自检脚本本身是 Rust `window.eval` 注入的，Chromium 不会给注入脚本套 CSP，`eval` 会被放行 → 假绿） | 改为监听 `securitypolicyviolation` 事件，并断言 legacy 内联脚本产生的全局函数（`window.t`、`window.detectSystemLang`）存在，证明「页面脚本真的跑起来了、不是只跑 shim」 |
| **S3-D08** | B1 收敛成单一来源：`contains_path`（组件级比较，不是字符串前缀）+ `join_within`（白名单名 + 包含断言），所有模组目录拼路径统一走它 | 原来 `plan.rs`/`pkg.rs`/`registry.rs`/`desktop.rs`/`submit.rs`/`scaffold.rs` 各拼各的；`mods-evil` vs `mods` 这类同级目录前缀绕过只靠一处实现防住，改一处即全局生效 |
| **S3-D09** | B4 用 `TerminalInput<'a>` 把明文**收进不可 Debug/Display 的类型**（只输出 `<redacted:N bytes>`），`PtyManager::write` 只收这个类型 | 「记得别写日志」靠人不如靠类型：调用方就算 `{:?}` 也拿不到明文，只有 `bytes()` 能取 |
| **S3-D10** | B5 的密码传输做**双轨兼容**：候选脚本含 `--password-stdin` 就把占位符 `PASSWORD_SLOT` 换成该标志、密码写 stdin；老脚本则替换成真密码走 argv | 随包脚本已加固（`vendor/cli/account-cli.js`），但用户可能带旧脚本；双轨保证不炸，同时 `CliOutcome::password_via_stdin` 让调用方能断言「本次确实走了 stdin」 |
| **S3-D11** | B5 的 `node_executable()` **找不到就 fail closed 报错**，绝不回退到裸名 `node` | 裸名会走 PATH 搜索，是 B5 的原始漏洞；宁可功能报错并给出明确文案，也不静默降级 |
| **S3-D12** | B7 的扫描正则**在脚本里反向拼接**（`"[A-Za-z]:" + SEP + … + "Users"`），注释里也不写真字面量 | 否则扫描脚本自己就是唯一命中项；同时跳过 `docs/`、`contract/`、二进制与 `.json`（这些可能合法地引用示例路径） |
